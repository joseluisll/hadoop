# T00019 — 3.5 ground truth: the manifest becomes archive-derived (2026-11-09 20:20 CET)

Third dist run on `feat/LICENSES-3.5` (42682946618, commit
`254e6b6fa31`) built the tarball WITH the YARN UI WARs restored
(`-Pyarn-ui`; the profiles live in the module poms) and published its
full ground truth. The archive asset gate PASSED unmodified — every
trunk-derived npm pin validated against 3.5's UI lock files (lock pins,
source package.json, pin exceptions). The only gate failure left was
R38, which this commit resolves the designed way: the committed
LICENSE-binary becomes the manifest generated from the run's own
archive enumeration + inventory (the R40 artifact-of-record flow).

## What changed

- **LICENSE-binary regenerated** from run 42682946618's data
  (`generate-archive-manifest.py --inventory THIRD-PARTY.txt
  --archive-tsv archive-jars.tsv`): 218 g:a (219 version lines),
  123 asset lines, 9 sections; the emitter derives 66 shipped texts
  from it. This is the first 3.5 manifest derived from what the
  3.5.1-SNAPSHOT tarball actually contains.

  checker-framework, checker-qual, dom4j, google-auth, hsql, jdom,
  threetenbp — none of these components ship in 3.5.1-SNAPSHOT (all
  verified absent from the archive enumeration; the dependency set
  moved on since the 3.5.0 release). The hsql text had been ported one
  commit earlier for the manual manifest's HSQL section; with the
  manifest now archive-derived and hsqldb not shipping, it is stale
  again — deleted with its alias row (checker-framework alias row too).
- **notice-exceptions adapted**: 7 stale rows dropped (the google-cloud
  gax/eclipse-collections family and org.jacoco.agent — components
  gone from 3.5.1-SNAPSHOT), 1 row added (azure-keyvault-core: shipped
  MIT section text carries no per-component copyright line). 32 rows
  before → 33 rows now, all consumed by uncovered components.
