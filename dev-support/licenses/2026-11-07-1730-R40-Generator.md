# R40 generator: archive-derived LICENSE-binary, 2026-11-07 ~17:30

Stage 3 opens: `dev-support/licenses/generate-archive-manifest.py`
derives the shipped manifest from the archives' enumerated contents
(R36 TSVs), resolving each third-party artifact's license from the
collected inventory and applying the R28 multi-license policy in code
(prefer Apache-2.0, then EDL, then EPL-2.0; jersey/hk2 keep the
combined section; jdom2/dom4j keep their named sections; hdrhistogram
keeps BSD-2). Inputs: both archives' TSVs + THIRD-PARTY.txt +
`archive-jar-mappings` (promotion, same rule as the gate) +
`shaded-jars` (embedded coordinates, inventory-resolved versions) +
the new curated `manifest-template.txt` (ASF preamble + Apache text)
and `manifest-assets.txt` (the 120 non-jar native/webapp/npm entries,
section-tagged). Fail-closed throughout: an archive jar absent from
the inventory, an uncurated multi-license set, or a zero-row
enumeration is a hard error.

## Scope note (NOTICE-binary)

NOTICE-binary is NOT generated: its per-component attribution corpus
(SciPy-derived code, Minpack, AWS JetS3t, ...) is curated prose that
cannot be derived from jar metadata. It stays hand-maintained and is
protected by the R10 drift gate. R40 is therefore landed for
LICENSE-binary; NOTICE-binary generation remains open.
