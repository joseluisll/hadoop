# API changes between baseline and candidate that phase A accepts, found by
# lib/api_compat.py in the classes that change: Hadoop's jars, the third-party
# jars on the Hadoop classpath (what Maven consumers of the non-shaded
# artifacts also get) and the shaded client jars. It fails on every
# breaking, implementor, jpms or jre finding no rule here matches.
#
# Format: <kind> <regex>  # <ticket>: <why>; announced: <where users are told>
# Both regexes match the whole kind and subject. Subjects:
#   <old jar> -> <new jar>|<class>[#<member>]   or  <jar>|<class>[#<member>]
#   <old jar> -> <new jar>                      (jar-module-name-changed,
#                                                jar-class-version-raised)
# with jars relative to the distribution. Say where the impact is announced
# ("announced: HADOOP-19970 release note"); a rule without it, or with
# "announced: no", shows in the report as an impact nobody was told about.

# --- HADOOP-19970: the servlet API moves to jetty-servlet-api 4.0.9.
# Servlet 4.0 adds abstract methods to ServletContext. Callers are unaffected;
# code that implements ServletContext and compiled against javax.servlet-api 3.1.0
# (direct consumers of hadoop-common got only that jar) must add them.
api-abstract-method-added javax\.servlet-api-3\.1\.0\.jar -> jetty-servlet-api-4\.0\.9\.jar\|javax\.servlet\.ServletContext#(addJspFile|getSessionTimeout|setSessionTimeout|getRequestCharacterEncoding|setRequestCharacterEncoding|getResponseCharacterEncoding|setResponseCharacterEncoding)\(.*  # HADOOP-19970: Servlet 4.0 ServletContext methods; announced: HADOOP-19970 release note
# JPMS module name of the servlet API: java.servlet (jakarta 4.0.4) and
# javax.servlet.api (3.1.0, derived) become jetty.servlet.api (module-info).
jar-module-name-changed (jakarta\.servlet-api-4\.0\.4|javax\.servlet-api-3\.1\.0)\.jar -> jetty-servlet-api-4\.0\.9\.jar  # HADOOP-19970: module jetty.servlet.api; announced: HADOOP-19970 release note
